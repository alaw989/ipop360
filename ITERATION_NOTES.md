# Iteration Notes

## Goal
Fix spec-099 (specs/099-detailmap-leaflet-leak.md), verified against current code on 2026-09-01 — resources/js/Components/DetailMap.vue matches the spec exactly (only line numbers shifted slightly): onMounted (~line 89-91) does setTimeout(initMap, 200) without storing the timer id; onUnmounted (~line 93) only calls destroyMap(), never clears that timer; the lat/lng watch (~line 95-103) calls destroyMap() then re-arms ANOTHER setTimeout(initMap, 200) without clearing any prior pending timer either. If a user navigates away from Restaurants/Show within 200ms of mount (fast back-click), or the watch re-fires near unmount, initMap() runs AFTER destroyMap() — it allocates a new L.map onto a mapContainer that's leaving/left the DOM, the orphaned mapInstance is never .remove()d, tiles keep loading, and Leaflet logs 'Map container is already initialized' / null-ref errors. Fix per the spec: (1) hold a module/closure-scoped let initTimer: ReturnType<typeof setTimeout> | null = null; (2) onMounted sets initTimer = setTimeout(initMap, 200); (3) onUnmounted clears it: if (initTimer) clearTimeout(initTimer); then destroyMap(); (4) in the watch callback, clearTimeout(initTimer) (if set) BEFORE calling destroyMap() and re-arming a new setTimeout, and store the new timer id back into initTimer; (5) at the top of initMap() (~line 37-38), add a guard so it's a no-op if the container is gone or already detached from the DOM: if (!mapContainer.value || !document.contains(mapContainer.value) || props.lat == null || props.lng == null) return; — keep the existing lat/lng null check, just add the document.contains() check alongside it. No behavior change on the happy path (normal mount/unmount/lat-lng-change should render the map exactly as before) — this only closes the 200ms race window. Add Vitest coverage in resources/js/Components/__tests__/DetailMap.spec.ts: mount the component, advance timers/unmount before the 200ms fires (vi.useFakeTimers or similar — check how the existing spec file mocks Leaflet/timers first and follow its conventions), and assert initMap's L.map(...) constructor is never called after unmount (no orphaned map instance) — prove the test is meaningful by temporarily removing the clearTimeout guard and confirming it goes red, then restore. Frontend-only, single file (DetailMap.vue) + its test — do not touch any PHP/backend files. Keep every existing Vitest case green.
