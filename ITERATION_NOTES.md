**Gotchas**: `Head` from `@inertiajs/vue3` must be explicitly stubbed in the `vi.mock()` factory (not just in the `stubs` object). When mocking `router.visit` via `vi.mock`, the spy must be created in `vi.hoisted()` to avoid hoisting order issues. `Link` stub template must bind `:href="href"` for attribute assertions to work. Date tests using UTC midnight can cross the date line in local timezone — use noon UTC or later. `JsonLd` component must be stubbed alongside `SeoMeta` and `AppLayout`. To assert on mocked composable calls (e.g. `useSeo`), import the mocked module at top level after `vi.mock()` — do not use `await import()` inside `it()` blocks (oxc parser rejects top-level `await` in non-async functions). For lucide icons used in `<script setup>` components, use `vi.mock('@lucide/vue')` with trimmed-down component stubs rather than `stubs` object — the stubs dictionary doesn't match `<script setup>` local component bindings. Compare page uses `ArrowLeft` from lucide-vue — must be in `vi.mock('@lucide/vue')`, not in stubs. `green-600` highlighted cells use `findAll('.text-green-600')` selector for assertions. **Admin pages that use `route()`**: provide it via `global.config.globalProperties.route` with a `mockRoute` function accepting `(name, params?)`. Use `vi.hoisted()` to create spies shared between `vi.mock()` factory and test body (e.g. `usePage` mock for flash messages). `router.get`/`router.delete` must be in the inertia mock as plain objects with `vi.fn()` methods. Cards in Admin dashboard use decomposed `Card`/`CardHeader`/`CardContent`/`CardTitle` stubs rather than a single `Card` stub — each must be in the stubs object. **Mocking `useForm`**: store form data in preset variables (`presetErrors`, `presetProcessing`) set before mount, and have the `vi.mock` factory merge them into the reactive form returned by `useForm`. Use `vi.hoisted()` for the `useFormMock` spy, then `mockImplementation` in the async factory to access `reactive` from Vue. Also set `(globalThis as any).route` for `route()` calls inside `<script setup>` submit handlers.
